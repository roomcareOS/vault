# Open Source Tools (YFarmX)

**The strategy, set 6 August 2026:** [[YFarmX]] releases small, genuinely useful open-source tools on GitHub to earn stars and attention. They are **not separate businesses and not separate projects** — they are YFarmX marketing that happens to be software.

## Why it works for this business specifically

YFarmX's problem is audience, not capability (see [[Mega Monetisation Plan]] — every revenue rung is gated on people arriving). A developer tool that solves one irritating problem well gets shared in places a news article never reaches, and the audience it brings is exactly the frontier-tech readership the site is written for. Stars are a vanity metric on their own; the point is the traffic, the backlinks and the credibility they carry back to yfarmx.com.

## The rules for anything released this way

1. **One tool, one irritating problem, solved properly.** Small and finished beats broad and half-built.
2. **It must stand on its own in public.** README that explains itself in thirty seconds, a licence, security posture, and a contribution route — see [[Project Practices (Scenecast)]] for the shape that already works.
3. **It carries YFarmX quietly.** Attribution and a link, never a sales pitch inside the tool.
4. **It never touches business data.** These repos are public; nothing about the five businesses, no private vault content, no customer anything.
5. **It goes in the YFarmX GitHub organisation**, not under the personal account — see the org-split card on the board.
6. **Ship it or archive it.** An abandoned public repo costs credibility rather than building it.

## What exists now

- [[Scenecast]] — the first one. A command-line tool that turns a logo and some clips into a finished on-brand video. Public, working, Phase 1 complete.

Future tools land here as notes alongside it.
