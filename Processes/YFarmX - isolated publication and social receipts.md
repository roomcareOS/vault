# YFarmX - isolated publication and social receipts

Use the current repository rules and Jay's authorisation in the active chat. The earlier August article pipeline describes retired automated deployment and scheduling behaviour. This note records the current corrections without including credentials.

## Finish the article package before publishing

Research primary sources, open every citation, run article preflight and an independent adversarial review, and complete the required lint and public-output checks. News articles have the house article read and fixed-cast podcast; reference sub hubs normally have neither. Use the current image typography rule: clean square bold mono on heroes and heavy clean proportional sans on infographics. Generate raster artwork with the requested Codex image tool.

Before paid audio synthesis, check that the local encoder and decoder dependencies load and the exact existing house podcast outro is available. Never substitute a voice, accent, cast or outro to solve a runtime failure. Upload finished MP3s at immutable media-origin URLs, verify exact served bytes and full decoding, then wire both modes into the top article player. On the podcast listing, check the player URL as well as the feed enclosure: a local source MP3 can make the build choose a local URL even when the release keeps audio on the media origin.

## Preserve the exact current live snapshot

Use an isolated own checkout. Fetch current main and read claims before writes. Snapshot the current canonical production deployment, its complete file map and its controls. Verify reused local bytes against that map before composing. Build only the approved pages and necessary derived lists, then retain canonical navigation, unrelated widgets, older card copy and old feed/search entries. Add only the own items to sitemap, feeds and search index. A complete hash audit must show that all unrelated live files are retained.

Run the official deployment script with the exact approved publish paths and the own deployment claim. Verify the live origin and sharing cards twice across their settle window. Release the deployment claim as soon as verified source integration reaches main; future social schedules do not need to hold deployment access.

## Integrate safely on Windows

Another session's Windows-invalid private filenames must remain unchanged. Use audited `merge-tree` and `commit-tree` integration without checking those files out. An alternative index can preserve the complete current tree while appending only own records and status entries. Merge own audio-manifest keys and cast-memory lines into the fresh branch values. Verify complete deltas, ancestry and divergence; push without force. Never rename, remove or normalise another session's private paths, switch the unrelated root checkout, or import unrelated staging drafts into a live release.

## Verify accepted social IDs

X and LinkedIn share the article's due time. The interval between articles is the interval Jay asked for, rather than an old fixed default. Use a private queue and check shared queues read-only for duplicates. Save each accepted ID before submitting the next post. Preserve accepted due times. Record actual `sentAt` and `externalLink` separately from acceptance. A follow-up checks only those IDs and stays silent while scheduled or unchanged. Once all posts are published, push own private receipts and the own completion entry to main and staging, release only explicitly owned article claims, then delete the verification follow-up.
