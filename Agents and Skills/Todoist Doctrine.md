# Todoist Doctrine

Jay runs all five of his businesses off **one Todoist account**, and every AI agent working in any repo is bound to keep it current. The founding logic, verbatim from the [[RoomCare]] operating instructions: *"If the board lags the work, he is managing a fiction."*

The division of labour, verbatim and estate-wide:

> **"Todoist owns STATE, the repo docs own the RECORD, the vault owns KNOWLEDGE."**

This vault is that vault. Live task state belongs on the board, the story of what shipped belongs in each repo's PROGRESS and docs, and the distilled how-and-why belongs here.

## The five projects (plus Inbox), and what belongs in each

| Project | What belongs |
|---|---|
| `Newsroom` | [[YFarmX]] articles ONLY. Board: 1. Idea → 2. Researching → 3. Draft with Jay → 4. Assets → 5. Staging → 6. Live + social. One card per article, named with the slug. See [[Article Pipeline (YFarmX)]]. |
| `YFarmX` | yfarmx.com work that is not an article: site, tooling, SEO, social. |
| `RoomCare` | roomcare.uk, the fundraise and the product. The [[RoomCare]] repo files here. |
| `Norwich Drones` | TikTok growth and the site for [[Norwich Drones]]. |
| `Apps` | Sections `myhomework.app` and `intervooh.com` — use the right section. Covers [[MyHomework]] and [[Intervooh]]. |
| `Inbox` | Anything needing Jay: a decision, a credential, a click only he can make. |

File work into the project for the repo you are in. **Do not invent projects.**

## The eight board rules

1. Read the board at the start of a session; somebody may already own the task.
2. Move the card when the state changes, not in a batch at the end.
3. Create a task for anything you discover and do not do.
4. Only close what is genuinely finished. If blocked, leave it open and say why.
5. Anything needing Jay goes in `Inbox` with enough context to act on without scrolling back: the exact screen, the exact value, the reason.
6. Never put a secret in a task. Name what is needed, never the value.
7. Task titles start with a verb and name the thing.
8. Todoist owns STATE, the repo docs own the RECORD, the vault owns KNOWLEDGE.

## If the connection is down

Say so plainly and put the items in the reply to Jay. Never silently skip the board, and never claim a card was filed when it was not.
